# v0.29.0

Nothing in this release needs a consumer change. `session`'s and
`completion`'s `SkillRunOptions`, `SkillCommand` and `SkillOutput` are now
aliases of new identical root types (`harness.SkillRunOptions` and so on), so
values pass between the packages without conversion. Code that converted
between them still compiles; a type switch with a case for both packages'
type no longer does, since they are now one type.

- Native runs no longer claim a known cache split when Claude or Grok omits
  the cache figures, keep every invocation's split rather than the latest
  one's, and refuse negative or overflowing token counts. Sessions and
  completion already did; all three now share one validator.
- A Grok prompt refused by the agent keeps the cause its refusal was
  classified with, such as rate limiting, on its `TurnError`.
- fx reports a tool's name only when it matches the tool's identifier, as
  Grok and Command Code already did.
- A short command run (as the sandbox probes use) whose output passes 4 MiB is
  refused with `ErrOutputLimit` rather than parsed from its first part. fx
  account inspection reads a long output the same way rather than failing
  with a short write.
- Session sandbox setup and skill delivery refuse an engine they do not name,
  rather than applying Claude's rules to it.
- The macOS command sandbox no longer computes a negative output limit.
- Claude's completion probe waits for its local server to stop before returning.
- `session.Event.Kind` and the turn statuses are documented in full.
- The rest is internal restructuring: the three agent-protocol engines share
  one prompt lifecycle, reply parser, update reader and configuration path,
  each engine has its own adapter files, and every support claim on every
  platform is pinned by a golden snapshot.
