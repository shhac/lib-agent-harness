# v0.23.1

Fixes for the command sandbox and session release. No API changes.

- macOS: sandboxed commands can use the owner's selected developer tools.
  `/usr/bin/git`, `make` and `cc` resolve the `xcode-select` choice through
  the `/var` symlink, which the profile could not read. Every check that used
  those tools failed with "No developer tools were found". The read set now
  also covers a selected Xcode's whole app bundle and the owner's Xcode
  license acceptance, not just `Contents/Developer`. The profile is now
  `seatbelt-workbench-v5`, so cached proofs are taken again on first open.
- `Release` no longer intermittently returns `ErrUnreclaimed` while a late
  process group is still being reaped (LAH-17).
