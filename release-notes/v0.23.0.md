# v0.23.0 (pending owner release)

Move the OS command sandbox and confined workspace access into the public
`sandbox` package. This is the next minor after the published v0.22.0 standalone
command API. No public name is removed and harness.Support is unchanged.

- New standalone names: `sandbox.Open`, `Options`, `Sandbox` (`Run`, `Start`,
  `Close`), `CommandRequest`, `CommandResult`, `StartedCommand` (`Stop`, `Done`,
  `Result`), and `CommandStartFailed`, `CommandOutcomeUnknown`,
  `CommandProcessLimit`, `CommandCleanupUnknown`, `CommandSandboxClosed`.
- Retained for one release, marked Deprecated: `session.OpenCommandSandbox`,
  `CommandSandboxOptions`, `CommandSandbox`, `CommandRequest`, `CommandResult`
  and `StartedCommand`. Request/result types alias sandbox's; options and
  sandbox/handle wrappers preserve the existing session error vocabulary.
  Session's five `Command*` constants and wrapper methods are also Deprecated
  and retain their behavior.
- Workspace names first released here: `sandbox.OpenWorkspace`, `Workspace`,
  `Config`; Workspace methods `Read`, `List`, `Search`, `Write`, `Edit`, `Close`,
  `Stuck`; `Result`, `Definition`, `Definitions`, `ResolveName`, `CheckDir`
  (Workspace method), `ToolError`, `RemoveReserved` (Workspace method), `SyncDir`, `Nested`, `Within`,
  `MaxResult`, `MinResult`, `ArgumentsInvalid`, `WriteFailed`, `WriteUnknown`,
  `ErrWriteUnknown` and `WorkspaceIOStuck`.
- Low-level command integration: `Prove`, opaque `Proof` (`SystemDirs`, `Binary`,
  `Identity`), `NewRunner`, `Runner` (`Execute`, `Close`, `Timeout`).
  Normalization, read rules and state-lock integration helpers remain internal.
  Callers of Runner own admission, validated directories, state locking and
  settlement; ordinary standalone use should call Open.
- Sandbox errors: `RefusalError`, `ProofError`, `CommandError`, `StateError`;
  sentinels `ErrUnsupported`, `ErrClosed`, `ErrCommandFailed`, `ErrStateLocked`.
  Codes `RefusedWorkDir`, `RefusedWorkbenchMountCheck`, `RefusedNotOffered`,
  `RefusedRuntimeHome`, `RefusedSandboxRead`, `RefusedLimit`, `RefusedConflict`,
  `CapabilitySandboxToolMissing`, `CapabilitySandboxToolOutdated`,
  `CapabilitySandboxNamespacesUnavailable`, `CapabilitySandboxUnavailable`,
  `CapabilitySandboxNotEnforced`, `CapabilityProbeTimeout`, `StateUnusable`,
  `StateLocked`, and the five command codes above. Session translates every
  sandbox error through fromSandbox.
- Move Seatbelt and bubblewrap profiles, checks, canaries, proof key functions,
  runners, supervisor, token/output and standalone recovery state into sandbox.
  Split its 64-entry-reset verification cache from session's native CLI cache.
  Keys retain seatbelt-workbench-v4, bwrap-workbench-v2 and the legacy session
  scratch shapes. Locks and token formats require no migration.
- Preserve Linux full re-proof and Start+Loopback refusal, macOS cached proof
  and inbound loopback witness, admission limit 64 and Close idempotence.
  Windows commands remain unavailable; native sessions remain supported.

crew-assistant and crew-code-review need no change: retained wrappers preserve
v0.22 behavior. New standalone use (including CA-62) should use sandbox.Open.
No dependency or CI matrix changes; the library remains CGO-free.

Owner steps after landing: run go vet and go test -race on macOS, Linux with
distribution bubblewrap and 0.8.0, and Windows; then tag/publish v0.23.0.
See [the boundary](../design-docs/2026-10-03-sandbox-package.md).
