# v0.24.0 (breaking)

Linux/macOS workbench read_file, search_files and edit_file are disabled until
workspace admission is verified. Standalone Workspace.Read/Search/Edit return
typed not_offered refusals before content I/O; WorkspaceRead and combined
WorkspaceWrite capabilities are unsupported.

API workbench Start/Open/Resume continue with list_files, opt-in write_file,
caller/skill tools and proved commands. Capabilities.WorkbenchTools reports the
configured surface, including unavailable tools and reasons. The model receives
an absence notice. All names stay reserved; forced calls cannot reach handlers.
Existing reference hashes and historical transcripts remain compatible.

This supersedes LAH-26's proposed whole-session refusal. The deterministic
retained-descriptor fixture models namespace reachability; it does not claim
exact reproduction of the reported Linux CI event. LAH-27/28 own restoration.
LAH-33/34 track consumer migration and validation against a published release;
no local dependency replacements are committed.

Review follow-up retains active Linux/macOS listing, formatter, write and
directory-swap controls, instruments edit's actual target open/read, and covers
concurrent refusal for all three content tools. Synthetic default/Write/Commands
Start/Open/Resume cases verify successful surviving writes and commands after
forced content refusals. The retained admission baseline runs alongside
containment tests without enabling content tools.

This release also ships the command execution policy correction and test fixes
prepared as v0.23.4, which was never tagged; see v0.23.4.md.

The [LAH-27 storage/admission design](../design-docs/2026-10-05-workspace-storage-admission.md)
is available for review; restoration on dedicated local filesystems remains
deferred to LAH-28 and consumer demand. Current refusal behavior is unchanged.
