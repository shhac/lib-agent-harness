# v0.33.0

Codex and Claude edge sessions launch, prove and resume as in v0.32.0, with
one new refusal for every engine: an edge whose CLI, helper, interpreter or
tool bridge lies inside the workspace or runtime home is refused with
`edge_conflict`, since the session could replace it. Install it elsewhere.

- Antigravity sessions can run inside the sandbox edge on macOS:
  `Sandbox.Edge` with the new `Edge.GeminiAPIKey`, and `Sandbox.Loopback`.
  agy keeps its Google-account login in the macOS Keychain, which the edge
  does not admit, so an edge session runs agy's Gemini API-key mode against
  generativelanguage.googleapis.com, billed to that key, not the
  subscription. A missing key refuses with `edge_token_required`, and a
  session without Loopback with `edge_conflict`: agy serves its language
  server on localhost. agy's own `--sandbox` is never passed.
- Loopback means an Antigravity edge session's egress is not provider-only:
  its commands can reach every on-machine TCP service, including a local
  proxy that relays further, as any edge session with Loopback can.
- All of `RuntimeHome/.gemini` is read-only to agy's commands, whatever agy
  loads from it, except the conversation, log and bookkeeping state it
  writes and the shell script it rewrites before each command. The library
  rewrites agy's settings, MCP list and default project before each launch,
  following no link and replacing rather than writing through a hard link.
- agy must be its native executable: a symlinked agy is granted as its
  target file alone, and a launcher script is refused, never a folder grant.
  It verifies TLS against the system `/etc/ssl/cert.pem` through
  `SSL_CERT_FILE`, not the keychain, and gets only pseudo-terminals the
  sandbox creates. An API-key login runs only in request-review, where agy
  denies commands that no `permissions.allow` rule grants; the library adds
  none, so an edge agy session reads and edits files but runs no commands.
  Hosted tools are not offered for it under the edge.
- The pre-launch canary drives one real agy `run_command` through a fake
  Gemini API and judges it as for Codex and Claude. It also proves writes to
  agy's settings and to loaders no rule names (plugin hooks, rules, agents,
  skills, installed executables) are refused, and that a terminal opened
  outside the sandbox stays unreachable. Checked against agy 1.4.12, locally
  only: CI does not install agy.
- `harness.SandboxEdge` reports Antigravity as Codex and Claude: Unknown on
  macOS, proved at each open; refused on Linux and Windows.
- fx is refused the edge (`harness.SandboxEdgeFxReason`): fx 0.0.14 ignores
  the proxy variables and dials its provider directly, so the edge's only
  egress cannot carry it.
- The edge's engine-specific choices now live in each engine's registry
  entry.
- Limits, recorded in the design doc: hard links planted before a session
  opens, from outside the sandbox, can alias a protected file to a writable
  one; workspace `AGENTS.md`/`GEMINI.md` stay writable, as for every engine;
  a runtime home whose path holds characters such as an apostrophe or `#`
  refuses with `edge_confinement_failed`.
- Not yet verified: a real Gemini API key under the edge, and production TLS
  through the system bundle. `AGY_CLI_DISABLE_AUTO_UPDATE=1` does not stop
  agy's own updater outside the edge; inside it the updater is refused.
