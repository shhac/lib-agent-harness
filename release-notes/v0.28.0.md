# v0.28.0

Nothing in this release needs a consumer change. `session.Policy` gains the
`FxPermission` field, which affects only positional `Policy` literals.

- Adds `harness.Fx` (`"fx"`), a CLI engine for fx, the terminal coding agent
  installed as `fx`, checked against a signed-in fx 0.0.14. Model discovery,
  account inspection (sign-in, team and AI Gateway credits), native runs and
  agent protocol sessions are offered.
  - Sessions run `fx acp`. Every session is put in fx's asking mode with
    `session/set_config_option`, and the mode, model and effort are read back
    from the configuration fx reports before the first prompt. A value fx
    refuses is refused. New `Policy.FxPermission` answers fx's permission
    requests: `FxDenyWhenAsked` (the default) or `FxAllowWhenAsked`, never an
    "always" option. A request with no matching option, or with duplicated
    options, is answered cancelled, and a mode switch is always rejected.
  - Asking mode is not read-only: fx asks before writes and shell commands but
    reads files and fetches web pages without asking. A denied tool fails and
    the turn carries on.
  - A turn reports its own usage, including cache reads and writes, and the
    context is fx's own figure. fx counts only the main agent's usage, not
    that of any agent it delegates to. Steering is composed; a resume reports
    a conversation fx no longer holds as gone.
  - Native runs are one `fx ask --json`, and `Config.Fx` takes
    `PermissionMode` (`ask`, `auto` or `full-access`). Empty is `ask` whatever
    the operator's saved interactive mode, and an asking run fails with
    `NonInteractivePermissionRequired` at its first write or shell command.
    A run's usage covers that run alone, also when resumed. A structured run
    is refused: fx states no output schema.
  - fx reads its profile from `~/.fx`, which no variable relocates, so another
    `Provider.CLI.Home` is refused, natively with the new
    `CodeHomeUnsupported`. Sessions inherit none of fx's `FX_` variables
    except the operator's protective `FX_MAX_AGENT_STEPS`, `FX_ULTRAFAST` and
    `FX_AUTO_UPGRADE`.
  - Constrained completion, restricted or sandboxed sessions, hosted caller
    tools, replacing instructions, compaction and quota are unsupported with
    reasons.
  - `examples/fxprobe` is a manual program that prints the fx capability
    claims beside live evidence from the installed CLI. It performs inference
    with the operator's own login.
