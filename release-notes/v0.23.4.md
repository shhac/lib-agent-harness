# v0.23.4 (not tagged; shipped in v0.24.0)

Command execution policy correction, proof-step facts and test fixes.

- Use `#!/bin/sh` PATH fixtures instead of relocated Apple shells or signing.
  Independently prove native refusal with an installed Darwin tool excluded
  from a disposable read policy, or an unmounted Linux ELF fixture.
- Anchor empty-PATH fallback writes to verified scratch; refuse replaced paths
  and changed ownership, with replacement/concurrent-replacement regressions.
- ProofError.Step and Facts.ProofStep expose fixed sanitized failing proof steps.
  Failed/interrupted checks certify nothing and create no command state.
- Owner-reported draft 3 (1b655a6) passed strict race and sandboxcheck on Ubuntu
  24.04/bubblewrap 0.9.0, but macOS 27 arm64 killed the relocated fixture and
  failed command-sandbox Open. Those results apply to draft 3, not this revision.

- Start errors after launch now include a settled handle, preserving bounded
  output and PATH diagnostics through Result, in the shared API. Compatibility propagation is deferred to LAH-30.
  Callers must inspect non-nil handles on error; pre-launch refusals remain nil.

- Execution-only Seatbelt/bubblewrap regressions use narrow process/sandbox
  prerequisites without loopback. Full network proofs retain loopback checks.
  Direct and replaced-path execution refusals are logged by focused verbose
  test runs (go test -v); ordinary CI runs don't print them.
- Supplied owner evidence establishes the macOS 27/v0.23.3 nvm-first PATH
  baseline (exit 139), and 734 passing tests after home PATH entries were removed.
  Corrected enforcement checks and platform CI require separate evidence.

- Commands filter inherited and caller-overridden PATH against their existing
  read policy. Canonical readable directories retain their order and duplicates;
  empty, relative, missing, non-directory, unresolvable and outside entries are
  dropped. An absent/all-dropped PATH uses fresh empty private scratch.
- One bounded, escaped `[harness PATH: ...]` stderr note explains drops, with
  fixed reasons and omitted counts. Run, Start/Result and low-level runners
  use the policy and bounds. Hosted/compatibility integration
  and settlement regressions move to LAH-30.
- macOS execution now shares data-read selectors and refuses unreadable binaries
  before startup. Linux retains its mount restrictions and proves inaccessible
  or permission-refused execution, without claiming macOS errno behavior.
- Stronger native-executable, interpreter and env-shebang canaries invalidate
  old evidence through Seatbelt v11, bubblewrap v4 and readable-path-v2 keys.
  The narrow Darwin native control individually grants sh's bash/dash/zsh
  dispatcher targets while retaining the unreadable native witness. Cancelled
  proof cleanup cannot publish evidence; cancelled cache hits are refused.
  This intentionally changes commands that relied on unreadable PATH entries,
  relative/cwd lookup or unrestricted macOS execution; explicitly grant Read
  to an external toolchain and its runtime files when appropriate.
- Network restrictions and harness.Support claims are unchanged. LAH-21 builds
  on this policy; native networking and access requests remain separate tasks.
  Runtime enforcement evidence and unrun platforms are recorded in the command
  design document; cross-compilation alone is not runtime proof.

- Command-sandbox checks skip proved refusals of nested OS sandboxes, loopback
  listeners, reserved atomic workbench temporaries, system-path access and Unix
  channel paths beyond the library's 90-byte limit. Bare
  EINVAL and other unexpected errors still fail; NO_SKIP still forbids skips.
- A CI re-exec fixture verifies skip/fail behavior inside the command boundary.
  The opt-in `go run ./internal/cmd/sandboxcheck` runner checks vet and race tests
  with cached dependencies and private scratch. Those test-only changes preserve capability claims
  and sandbox permissions; the command execution correction above changes execution.

Linux sandbox-check follow-up: the unsandboxed privilege escape control probes
/proc/self/status. Zero effective, permitted, inheritable and ambient capabilities
with NoNewPrivs=1 prove inherited confinement; only the privilege subtest skips
with a named one-line refusal. Filesystem, network and overlay assertions still
run. Missing or malformed status fails; permission-denied reads name their own
diagnostic. Real sandbox canaries still require privilege-ok.

Reclamation lease tests use a ready, live survivor in a dedicated group greater
than 1 instead of the inherited test group (which can be 1 under bubblewrap).
Early worker errors fail immediately; cancellation settles the worker, releases
the lease and preserves the launch marker. No production ownership rules change.

Nested refusal fixtures require the platform-specific capability prefix and a
nonempty diagnostic suffix. Linux uses bubblewrap 0.8.0+ and unprivileged
namespaces; abbreviated reports are not complete diagnostics. Joined refusal
errors are flattened to one line. NO_SKIP still fails refused prerequisites;
child normal/strict fixtures select their own mode independently of the parent.
The test fixes do not change permissions; the command execution correction above
does. harness.Support claims remain unchanged.

- Interrupted bubblewrap prerequisite trials fail before permission-refusal
  conversion in sandbox, session and re-exec checks. Cancellation and timeouts
  never justify skipping; the nested Seatbelt probe follows the same rule.
- Regressions execute the generated Linux privilege expression against synthetic
  statuses, validate complete normal/strict refusal output and require a live
  survivor response after lease cancellation, excluding zombie-only occupancy.
- CI pins Ubuntu 24.04 and verifies bubblewrap 0.9.x, retains strict macOS,
  Linux, Windows and upstream 0.8.0 coverage, verifies both parent fixture
  modes without outer skips, and repeats the lease test twenty times.
- Owner note 6 records baseline 106c711 Linux sandboxcheck failures in the
  privilege control and lease test, and a strict-suite failure in the nested
  refusal matcher. Drafts ad4b36b and b54ec5d passed Linux sandboxcheck and the
  strict race suite. Draft 1 also passed both on macOS; draft 2 passed macOS
  sandboxcheck but its strict suite hit the developer-tool first-launch timeout.

  now merged into this branch and retained. That focused result is distinct
  from a full strict-suite rerun.
- Aggregate owner successes establish corrected Linux execution. Raw baseline

  evidence to the owner's macOS/Linux runs outside the sandbox; results remain
