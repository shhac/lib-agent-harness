# Shared harness contract

Recorded 2026-09-16. Initial implementation extracted from agent-assistant and
agent-code-review; live checks used Codex CLI 0.154.0 and Claude Code 2.1.272.

## Boundary

The library owned local CLI mechanics. Applications retained orchestration,
prompts, budgets, permissions decisions, message queues, durable records, and
retry policy. The execution contract was explicit:

- Constrained completion disabled native tools and verified the actual outbound
  request with a rejecting local probe before inference. Tool calls were returned
  as proposals for application authorization.
- Native runs preserved configured CLI permissions, schemas, transcripts, and
  session resumption. Output files were cleared before each attempt.
- Interactive sessions provided a common method shape for both providers,
  including capability descriptions, streaming events, interruption and steering.

A native session was not an alternative implementation of the constrained
completion security boundary. Account headroom polling and price estimation
remained outside the initial library; invocation usage parsing was shared.

## Same interface, explicit semantics

Codex used its local app-server protocol. Claude used `claude -p` with streaming
JSON over stdin/stdout. The Go package did not depend on either provider's SDK.

Codex steering appended input to the current native turn. Claude steering was
composed from interrupt acknowledgement, terminal result, and a new user turn
in the same process. A native-only requirement rejected composed steering.
Queueing another message remained a caller decision.

Capabilities were native, composed, unsupported, or unknown. Unknown indicated
an operation not yet verified against the installed CLI. Server rejection was
distinct from uncertain delivery or a broken transport: an acknowledged refusal
could leave a session usable; an uncertain control request terminated it rather
than risking later work receiving a stale prompt.

Native CLI tools could already have produced external effects when interrupted.
No interrupt implied rollback. Claude's interrupted terminal result used an
execution-error subtype without a definitive cancellation marker. The normalized
result therefore preserved the native error flag even when correlating a
requested interrupt; it could not prove interruption was the only cause.

## Identity and credentials

Binary and home selection were per configuration. Native credentials remained
with the CLI; the library never copied them. Claude needed USER in its real
execution environment for native macOS keychain lookup. Its rejecting probe
used a disposable home and dummy credential without USER. Selecting the default
Claude home explicitly preserved its native keychain namespace.

Resume references bound session ID to home, working directory, binary selection,
model, effort, instructions, policy, and a caller-supplied account label. They did
not detect a person changing accounts inside an existing home. Reference files
belonged in private application state because they contained filesystem paths.

## Validation

Synthetic tests covered stream parsing, transcript fixtures, stale result files,
resume usage accounting, missing usage, malformed messages, model discovery,
capability probes, event-buffer overflow, control races, cancellation, and
subprocess containment. Linux/macOS/Windows CI used no paid models.

Live text-only tests exercised Claude Haiku at low effort through the Go session
API: start, composed steering with remembered context, process close, native
resume, and another context-preserving turn. Native Codex steering was checked
with Luna at low effort, including close/resume with retained context. Model discovery on both installed CLIs returned metadata
without inference. Live tests were manual and did not join the automated suite.

## Initial limits

Interactive user input was text-only. Server permission and user-input requests
were denied; there was no application approval callback yet. There was no silent
restart fallback after transport loss. Turn events were bounded and had to be
consumed while a control operation waited. Usage absent after interruption stayed
unknown. Windows scratch directory privacy relied on an owner-restricted parent
ACL, since POSIX mode bits do not establish a Windows DACL.
